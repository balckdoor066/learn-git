AI Lab — Software Factory

สภาพแวดล้อมแซนด์บ็อกซ์ที่ AI บิลด์ ทดสอบ และส่งมอบ — คุณแค่วาง URL

ภาพรวม

AI Lab คือระบบบิลด์แบบ self-hosted ที่รับ URL ของ GitHub repository โคลนเข้าไปใน Docker sandbox ตรวจจับภาษาและเฟรมเวิร์ก ติดตั้ง dependencies รันเทสต์ และสร้างสรุปจาก AI โดยอัตโนมัติ ทั้งหมดทำงานบนเซิร์ฟเวอร์ OpenClaw ของคุณ

ฟีเจอร์หลัก

ตรวจจับภาษาอัตโนมัติ • บิลด์ใน Docker sandbox • อัปเดตแบบเรียลไทม์ผ่าน WebSocket • สรุปเทสต์โดย AI • แดชบอร์ดสองภาษา (EN/TH) • REST API • ประวัติการบิลด์ • การแจ้งเตือน Toast

เริ่มต้นอย่างรวดเร็ว

สิ่งที่ต้องมี

  • Node.js v18 ขึ้นไป ติดตั้งบนเซิร์ฟเวอร์
  • npm ตัวจัดการแพ็กเกจ
  • Docker (สำหรับบิลด์ใน sandbox)

การติดตั้ง

# คัดลอกไฟล์ไปยังเซิร์ฟเวอร์
mkdir -p ~/ailab
scp index.html style.css script.js server.js bear1234@192.168.2.38:~/ailab/

# ติดตั้ง dependencies
cd ~/ailab
npm init -y
npm install ws

# เริ่มเซิร์ฟเวอร์
PORT=8081 node server.js

สำเร็จ

AI Lab ทำงานแล้วที่ http://192.168.2.38:8081/

หน้าจอแดชบอร์ด

แดชบอร์ดประกอบด้วย 4 หน้าหลักที่เข้าถึงได้จากเมนูด้านข้าง

หน้ารายละเอียด
หน้าหลักเมนูลัด, ฟอร์มบิลด์ใหม่, สถิติภาพรวม, บิลด์ที่กำลังทำงานและล่าสุด
ประวัติประวัติการบิลด์ทั้งหมดพร้อมการค้นหาและตัวกรองสถานะ
เชื่อมต่อการตั้งค่าปลายทางเซิร์ฟเวอร์, สถานะการเชื่อมต่อ, บันทึกกิจกรรม
ตั้งค่าค่าเริ่มต้นการบิลด์ (หมดเวลา, หน่วยความจำ, CPU), ตั้งค่า AI, การแจ้งเตือน

แถบการทำงาน (Action Bar)

แถบการทำงานด้านบนให้เข้าถึงฟังก์ชันหลักได้อย่างรวดเร็ว:

  • บิลด์ใหม่ — ไปที่ฟอร์มบิลด์และโฟกัสที่ช่อง URL
  • ดีพลอย — ไปที่หน้าเชื่อมต่อ
  • เทอร์มินัล — เข้าถึงเทอร์มินัลเซิร์ฟเวอร์ (เร็วๆ นี้)
  • เอกสาร — คู่มือนี้

ไอคอนเมนู

กริดไอคอนบนหน้าหลักเป็นทางลัดไปยังฟีเจอร์หลักทั้งหมด แต่ละการ์ดไอคอนคลิกได้และนำทางไปยังหน้าหรือฟีเจอร์ที่เกี่ยวข้อง

ส่งงานบิลด์

  1. ไปที่หน้า หน้าหลัก
  2. วาง URL ของ GitHub repository ในช่อง (เช่น https://github.com/user/project)
  3. คลิก บิลด์
  4. งานบิลด์จะปรากฏในส่วนบิลด์ที่กำลังทำงานพร้อมแถบความคืบหน้า
  5. การอัปเดตแบบเรียลไทม์ส่งผ่าน WebSocket

หมายเหตุ

ถ้าไม่ได้เชื่อมต่อกับเซิร์ฟเวอร์ บิลด์จะทำงานในโหมดสาธิต/จำลองพร้อมขั้นตอนตัวอย่าง

สถานะการบิลด์

แต่ละงานบิลด์มีสถานะต่อไปนี้:

สถานะป้ายความหมาย
RUNNINGกำลังทำงานบิลด์กำลังดำเนินการ
PASSEDผ่านเทสต์ทั้งหมดผ่าน
WARNINGคำเตือนเทสต์บางรายการมีคำเตือน
FAILEDล้มเหลวบิลด์หรือเทสต์ล้มเหลว
TIMEOUTหมดเวลาบิลด์เกินเวลาที่กำหนด

รายละเอียดการบิลด์

คลิกการ์ดบิลด์ใดก็ได้เพื่อเปิด modal รายละเอียด ประกอบด้วย:

  • สถานะ, ภาษา, ระยะเวลา, เทสต์ — สรุปสถิติด้านบน
  • สรุปจาก AI — การวิเคราะห์ผลลัพธ์โดย AI
  • ขั้นตอนการบิลด์ — โคลน → วิเคราะห์ → ติดตั้ง → บิลด์ → เทสต์ → ตรวจสอบ → แพ็กเกจ
  • บันทึกการบิลด์ — ผลลัพธ์จากเทอร์มินัลพร้อมไฮไลท์

ขั้นตอนไปป์ไลน์การบิลด์

#ขั้นตอนรายละเอียด
1โคลน RepositoryGit clone repo เข้า sandbox
2วิเคราะห์โปรเจกต์ตรวจจับภาษา, เฟรมเวิร์ก, dependencies
3ติดตั้ง Dependenciesรันตัวจัดการแพ็กเกจ (npm, pip, cargo, ฯลฯ)
4บิลด์โปรเจกต์คอมไพล์หรือบันเดิลโปรเจกต์
5รันเทสต์รันชุดเทสต์ทั้งหมด
6ตรวจสอบคุณภาพLint, coverage, ตรวจสอบความปลอดภัย
7แพ็กเกจผลลัพธ์สร้าง build artifacts

ประวัติและตัวกรอง

หน้าประวัติแสดงบิลด์ทั้งหมดที่ผ่านมาพร้อมตัวเลือกการกรอง:

  • ค้นหา — กรองตามชื่อ repository
  • ตัวกรองสถานะ — ทั้งหมด, ผ่าน, คำเตือน, ล้มเหลว, หมดเวลา

การ์ดบิลด์แสดงชื่อ repo, ป้ายสถานะ, ภาษา, ผลเทสต์, ระยะเวลา, และเวลาสัมพัทธ์

เชื่อมต่อเซิร์ฟเวอร์

หน้าเชื่อมต่อจัดการลิงก์ระหว่างแดชบอร์ดและเซิร์ฟเวอร์ AI Lab

ช่องการตั้งค่า

ช่องค่าเริ่มต้นรายละเอียด
URL โฮสต์http://192.168.2.38:8081URL หลักของเซิร์ฟเวอร์
เส้นทาง API/apiคำนำหน้า REST API endpoint
เส้นทาง WebSocket/wsWebSocket endpoint
โทเค็นยืนยันตัวตน(ว่าง)โทเค็นยืนยันตัวตน (ถ้ามี)

ขั้นตอนการเชื่อมต่อ

  1. ป้อน URL โฮสต์
  2. คลิก บันทึกและเชื่อมต่อ
  3. แดชบอร์ดส่ง ping ไปที่ GET /api เพื่อตรวจสอบเซิร์ฟเวอร์
  4. ถ้า REST สำเร็จ จะเปิดการเชื่อมต่อ WebSocket ที่ /ws
  5. จุดสถานะเปลี่ยนเป็นสีเขียวเมื่อสำเร็จ

เหตุการณ์ WebSocket

การเชื่อมต่อ WebSocket ช่วยให้อัปเดตแบบเรียลไทม์จากเซิร์ฟเวอร์

ประเภทเหตุการณ์ทิศทางรายละเอียด
connectedเซิร์ฟเวอร์ → ไคลเอนต์ส่งเมื่อเปิดการเชื่อมต่อ
build:startedเซิร์ฟเวอร์ → ไคลเอนต์ส่งบิลด์ใหม่
build:progressเซิร์ฟเวอร์ → ไคลเอนต์อัปเดตความคืบหน้า (0–100)
build:completedเซิร์ฟเวอร์ → ไคลเอนต์บิลด์เสร็จสิ้นพร้อมผลลัพธ์
pingไคลเอนต์ → เซิร์ฟเวอร์ตรวจสอบ heartbeat
pongเซิร์ฟเวอร์ → ไคลเอนต์ตอบกลับ heartbeat
webhookเซิร์ฟเวอร์ → ไคลเอนต์ส่งต่อ webhook ภายนอก

ตัวอย่างข้อความ

// เซิร์ฟเวอร์ → ไคลเอนต์: ความคืบหน้าบิลด์
{
  "type": "build:progress",
  "job_id": "20260412082500-a1b2c3",
  "progress": 65
}

// เซิร์ฟเวอร์ → ไคลเอนต์: บิลด์เสร็จสิ้น
{
  "type": "build:completed",
  "build": {
    "job_id": "20260412082500-a1b2c3",
    "repo_url": "https://github.com/user/project",
    "status": "PASSED",
    "duration_seconds": 14,
    "tests": { "total": 24, "passed": 24, "failed": 0 },
    "ai_summary": "บิลด์เสร็จสมบูรณ์ เทสต์ทั้งหมดผ่าน"
  }
}

เชื่อมต่อใหม่อัตโนมัติ

ConnChannel จัดการการหลุดของการเชื่อมต่อโดยอัตโนมัติ:

  • Ping เป็นระยะ — ตรวจสุขภาพ REST ทุก 30 วินาที
  • เชื่อมต่อ WebSocket ใหม่ — เชื่อมต่อใหม่อัตโนมัติเมื่อตัดการเชื่อมต่อ
  • ตัวบ่งชี้สถานะ — จุดสถานะในเมนูด้านข้างและแถบการทำงานแสดงสถานะการเชื่อมต่อ
  • บันทึกกิจกรรม — เหตุการณ์การเชื่อมต่อทั้งหมดบันทึกในหน้าเชื่อมต่อ

API อ้างอิง

เซิร์ฟเวอร์ AI Lab เปิด REST API บนพอร์ตเดียวกับแดชบอร์ด

Nginx Reverse Proxy (ถ้าต้องการ)

เพื่อให้บริการ AI Lab ภายใต้โดเมน OpenClaw:

# /etc/nginx/sites-available/ailab
server {
    listen 80;
    server_name ailab.local;

    location / {
        proxy_pass http://127.0.0.1:8081;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
    }
}

Systemd Service

เพื่อให้ AI Lab ทำงานต่อเนื่องหลังรีบูต:

# /etc/systemd/system/ailab.service
[Unit]
Description=AI Lab Server
After=network.target

[Service]
Type=simple
User=bear1234
WorkingDirectory=/home/bear1234/ailab
ExecStart=/usr/bin/node server.js
Environment=PORT=8081
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target
# เปิดใช้งานและเริ่ม
sudo systemctl daemon-reload
sudo systemctl enable ailab
sudo systemctl start ailab

# ตรวจสอบสถานะ
sudo systemctl status ailab

ภาษา (EN/TH)

แดชบอร์ดรองรับภาษาอังกฤษและภาษาไทย สลับภาษาโดยใช้ปุ่ม EN/TH ในเมนูด้านข้าง

  • การตั้งค่าภาษาบันทึกใน localStorage ภายใต้คีย์ ailab-lang
  • องค์ประกอบ UI ทั้งหมดใช้แอตทริบิวต์ data-i18n สำหรับการแปล
  • ฟังก์ชัน t(key) แปลงคีย์การแปล
  • ใช้ภาษาอังกฤษเป็นค่าเริ่มต้นถ้าไม่มีการแปลภาษาไทย
